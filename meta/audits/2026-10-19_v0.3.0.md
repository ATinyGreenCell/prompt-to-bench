# Release audit for v0.3.0: claims, data and tooling

**Snapshot.** HEAD `addf4d7` plus the working tree, 19 Oct 2026, about 18:45–22:10.

**Context.** The NPU-box sweep and a laptop run of a ternary 27B model were still running. Separate Claude agents, working read-only and recomputing from the data with the repository's own scripts, audited in three passes. The first pass covered the four commits since 18 October: v11, the box Gemma comparison, the laptop Qwen3.5 9B row and the Terminal-RSI citation. The second covered this release's new text, data and code. The third checked the second pass's fixes. Like the earlier audits, this was done by Claude, which also wrote the work, so it is not independent review.

## First pass: the four commits since 18 October, and the new text

### Fixed: claims

- **Abstract, geometry ranking.** "The most of any laptop model" was attached to the fine-tuned 7B's mean geometry score, 0.32, but Gemma 4 E2B's is 0.34. It now refers to renders on the first try (14 of 16, the most).
- **v11 against v9** (abstract, §6.4, conclusion). "Gained nothing beyond the spread" and "neither run clearly beat" understated v11.
  - v11 equals or slightly exceeds the better of v9's two runs on most measures. The score rose after 11.0% and 8.3% of feedback messages, against 5.3% and 7.8%, and one run passed 22 samples against 15.
  - The margins are smaller than the gap between v9's own two runs (27% and 43% of files changed).
  - The text now says "at most a little".
- **v10 "within the range of v9's two runs."** Its score rose after 4.8% of messages, just below v9's 5.3%. The text now says so.
- **"v11 combines the two changes that held up."** v6 was a single training run. The text now reads "two changes that had looked useful (v6, a single training run)".
- **"Agreed more closely than any earlier pair."** True for tasks, not for samples passed (16 against 22). The text now reads "on what they passed".
- **Rounding.** "A fresh draw would pass 3.7 ± 0.5": 3.6486 rounds to 3.6.
- **Qwen3.5 9B cut-offs.** "13 of 16 first replies cut off at the cap": 12 hit the cap and one was stopped for repeating itself.
- **"In the four complete runs (...), 37-42 of 48."** With Qwen3.5 9B complete it is five runs, 32-42.
- **v7 "a held-out mean best of 0.50, as high as any model's."** v9 (0.52) and v10 (0.51) are higher. The text now reads "against v4's 0.42".
- **"The 96-hole PCR rack ..., which no other model passed."** Now limited to Table 8; Claude Sonnet 5.5 and Gemma 4 26B also passed it.
- **"Met half the checks on 6 tasks"** is 5-6 (Gemma 4 E2B 5, E4B 6).
- **"A single training run moves a model by two or three tasks."** The seed pairs differ by 2, 3 and 1, so it now reads "up to three".
- **Terminal-RSI citation.** "Five stages" counted the base model; there are four training stages. The reference is shortened to six authors and "et al.", like most entries.
- **Table order.** Table 11 (the held-out families) appeared before Tables 9 and 10. The tables are renumbered in order of appearance (9 held-out families, 10 harness search, 11 harness on the 16 tasks), with the references in `finetune/README.md` and `bench/README.md`.
- **Made stale by the new results:**
  - "No local model passed a task" (§6.1);
  - "We did not test larger models" (§7);
  - the box-platform limitation's section reference (§5.2, now §5.4 and §6.5);
  - the snapshot date;
  - the header version.

### Fixed: data and tooling

- **`bench/sample_stats.py`.** It counted a conversation twice when it had been redone, and counted records flagged `needs_rerun`.
  - It now keeps the newest record per conversation and drops flagged ones, as `analyze.py` does.
  - Outputs are byte-identical before and after for all 21 GPU runs and the box fine-tune runs (`finetune_table.py`, `repair_stats.py`, `self_consistency.py`, `sample_stats.py`). Only the sweep's own folder changes, from 531 to 528 records.
  - Regression test: `stats_redact_edges` in `bench/test_harness.py`.
- **Private address and home paths in the box's provenance files** (`box_*.json`). The build log already redacts these.
  - `meta/redact_results.py` now applies the build log's redaction to all 53 files; it is idempotent and has a test.
  - The address was already in five files committed on 19 October (`box-gemma-h0`). They are redacted from now on, but the address, a private home-network one, remains in the git history.
- **The scale figure** (new Figure 6) called every laptop point "4-bit".
  - A laptop model with its own runtime (the ternary 27B) now has its own marker, label and legend entry.
  - The y-axis has room under zero, so the low box models' labels no longer print over the axis.
- **The ternary model's run.** A server fault inflated one conversation's time about sevenfold.
  - Cause: llama-server's in-memory prompt cache filled the 16 GB laptop, and generation fell from about 2.5 to 0.3 tokens per second.
  - Fix: the server was restarted with `--cache-ram 0` (the first 8 tasks had run with the default cache).
  - The conversation was flagged and redone. The rule, fixed before the rerun: the new record supersedes the old, for its outcome and its time. It was redone from 21:25 to 21:41 at 2.5 tokens per second and failed again in three attempts, its first two files the same as before. Its 16 minutes replace 83, so the median time per task is 23.9 minutes instead of 25.2.
- **Box thinking-on samples.** The second samples were chosen after seeing the first. The run README, Table 13's caption and the limitations say so (the rule itself was corrected in the second pass, below).
- **Provenance READMEs:**
  - new for `main-bonsai`: the build, the fork commit, the server flags and the fault;
  - dated notes in `main-tiiny`: the pauses, taken from the sweep log, and the queue change;
  - a note in `think-tiiny` on how the second samples were chosen.

### Checked and unchanged

- Every other number in the four commits since 18 October:
  - v11's rows in Tables 8, 9 and 11;
  - the box Gemma comparison;
  - Tables 3-6 for Qwen3.5 9B;
  - the Terminal-RSI numbers, against its Table 2 and §3.3.

## Second pass: this release's text, data and code

The second pass read every new or changed sentence against the run data, the sweep's queue and logs, the provenance files and the build log, recomputed Tables 12 and 13 from the raw records, and drew Figure 6 at every Bonsai score still possible.

### Fixed: claims

- **"The only store model to reach the bar in any sample."** True only under the standard protocol: with thinking on, gpt-oss-120b passed 8 and 9. Both §6.5 sentences are now limited to the standard protocol, and gpt-oss-120b is named.
- **"Every language model in the store."** We ran 16 and left out the vendor's "Turbo" builds, an uncensored Qwen3.8 and BigBang (build log, 14 October). §5.3, §5.4, §6.5 and §9 now say so.
- **"Reran the models that can reason."** It was nine of the twelve: Qwen3 8B was still queued, and the two dense 27B models were never queued. §5.3, §6.5 and Table 13 now say so.
- **Ornith.** It was listed as always reasoning, but it reasons only when asked: none of its 90 thinking-off attempts carried reasoning, against 43 of 43 with thinking on. It is now `switchable` in `models.yaml` and the run README.
- **The rule for second thinking-on samples.** "First beat both standard samples" would also have picked Ornith (4 against 3 and 1) and GLM-4.7-Flash (1 against 0 and 0). The four were actually picked for gaining three tasks or more over the better standard sample (build log, 19 October 18:44 UTC). Table 13, §9 and the run README now give that rule.
- **"Room to reason helped the middle of the field."** Only gpt-oss-120b's gain rests on two samples. The other three are single samples, picked for their gain. The two Qwen3.5 models gained nothing, Ornith and GLM one task each, and the dense 27B models were not tested. The paragraph now says exactly that.
- **Statements the new results had overtaken:**
  - "only the hosted models produced correct parts" (§4);
  - "no off-the-shelf local model passed a task" and its best attempt (§6.2, §6.4);
  - "local models … passed nothing in English" (§6.3);
  - "the most parts of any local model" (§6.1, §6.4): the box also rendered 16 of 16, so it is now "laptop model";
  - "14 open-weight models" (contributions);
  - "those three conversations need to be run again": they were;
  - "their full results follow when the sweep ends" (§6.4);
  - "one run per model, one computer" (§9);
  - "three audits";
  - "every reference was checked on 5 October": two were added later, and both were checked against arXiv.
- **v11 against the better v9 run.** "Equal or slightly exceed" was not true of v11's first run, which had 4 tasks against 5 and 42% against 43%. It now reads "match or fall within a task and a point", with the score-rise counts: 25 and 18 messages against 12 and 18. The same change is in the conclusion and `finetune/README.md`.
- **Price and "offline".**
  - US$1,300 was the author's Kickstarter early-bird price, and every mention now says so.
  - After a power cycle, the box's model service answered only once the vendor's app was logged in again, and that was never tested without internet. The paper no longer calls the box offline, and §9 has a new limitation for it.
  - §7's "about half the tasks" now states the three-attempt bound, with feedback triggered by the hidden checks, and the first-try rate (a fifth).
- **Link and harness provenance.**
  - The box was reached over USB-C until 20:22 on 14 October, then over Wi-Fi.
  - The frozen harness copy started that afternoon.
  - The 16:48 records came from the change committed as `7a8ca5d` half an hour later.
  - §5.3, §9 and the run README now say so.
- **Smaller fixes:**
  - The ternary model keeps 0.1% of its weights in higher precision.
  - Its first 8 tasks ran with the server's default prompt cache.
  - Table 12 explains Gemma's third sample.
  - The box README cites the source of its firmware and memory figures.
  - The gpt-oss cut-off share is now given per model: 96 of 96 and 45 of 82.
  - The box README lists the three fine-tune tests of 16 October among those run during the pause.
  - The thinking-on README notes that the box ignores `num_ctx`.
  - The Gemma-h4 README cited the wrong table number.

### Fixed: code and data

- **`meta/redact_results.py`.**
  - Problems: it trimmed every string it redacted. It could rewrite a path that merely began with the home directory's name, and with `HOME=/` it would rewrite every "/".
  - Fix: it now matches the home directory only as a whole path component. It keeps whitespace, redacts keys and refuses keys that would redact alike. It also covers carrier-grade NAT and link-local addresses.
  - The earlier redaction of the committed files had changed nothing but the redacted values; checked against git.
- **`bench/sample_stats.py`.**
  - It now loads records exactly as `analyze.py` does:
    - damaged lines and non-records are skipped;
    - attempts after a rescored pass are dropped;
    - a prefix no longer picks up another run's folder.
  - Effect: no published number changes. Only the box sweep's own feedback count moved, from 956 to 954 messages, because of one rescored conversation.
- **Figure 6.**
  - Labels are now placed by measuring them in the final layout, so a long label can no longer print over another.
  - A laptop point that would hide a box point is drawn just beside it.
  - The legend uses the paper's runtime names.
  - The PNGs on disk had been drawn before the last code change. They are redrawn at release.
- **Tables 5 and 6** now mark a partial row, as Tables 3 and 4 do. The model table prints download sizes as Tables 3 and 12 do.
- **`bench/analyze.py`'s default run list** now produces the paper's tables. Before, it left out the fine-tuned and ternary rows.
- **Reruns.**
  - `run_bench.py` used to write a redone conversation's files over the old ones. It now moves them to `code/<model>/superseded/`.
  - The Bonsai rerun's predecessor was moved by hand before the rerun.
  - The box sweep's three reruns, run by its frozen copy of the harness, had already overwritten theirs; their records remain.
- **Build log.** A third party's name, from a direct message the author shared, and a sentence listing the credentials on the author's laptop are now redacted.

### Left as is

- Commit `cca7c28` holds the private address and home paths in five `box-gemma-h0` files. They are a home network's private address and a user name already on every page of this repository. Rewriting published history would break existing clones, and the tagged snapshot is clean.
- Already public in earlier commits: the box's `device_name` ("seb's Tiiny") and the laptop's host name.
- The two dense 27B models have no thinking-on run, and the sweep's queue was not changed for this release.

## Third pass: the second pass's fixes

A third read-only pass checked the second pass's fixes against the data, and tested the new figure code on real and edge-case input.

### Fixed

- **Claims the new results had overtaken:**
  - §6.4 still called the fine-tune's pass on the NPU box "the first local pass", and said passing there was "reachable but not yet reliable — 1 of 16". The store models had passed tasks on the same box two days earlier. Both sentences now refer to the fine-tune.
  - §9 said that re-checking with the final checker "changed one verdict", against §5.2's three NPU-box passes turned into failures. §9 now gives both.
- **Qwen3.8 27B is a Turbo build.**
  - The only Qwen3.8 27B in the store has the manifest `Qwen3.8-27B_turbo_20260819`, the vendor's speculative-decoding build. Its speed (25.7 tokens/s, against 6.1 for Qwen3.6 27B) fits that.
  - §5.4, §6.5, §9, `models.yaml` and the box README now say so. The §6.5 comparison with the ternary laptop model names the build.
- **"The largest gain we measured on the box."** gpt-oss-20b's single sample gained as much (4 against 0 and 0). Also, gpt-oss-120b's gain cost little time: a median of 5.7 against 5.4 minutes a task. The sentence now speaks of the one gain that held in two samples and gives both times. The heading states the three-task threshold behind "three more".
- **Offline and price wording.**
  - §7 Connectivity still implied that the box works offline; it now says this was not tested.
  - The price is now worded as what the author paid. The abstract and §7 no longer imply that it is a current price.
- **Box provenance.** Only the first 9 of the 48 `box_*.json` files hold `tiiny info` and `tiiny status`. After the move to Wi-Fi, the vendor's tool no longer found the box, and the files say so. The box README now says so too.
- **Smaller fixes:**
  - Qwen2.5-Coder 7B is the largest code model in the benchmark, not the largest model that runs on the laptop.
  - GLM-4.7-Flash's catalog says thinking is unsupported, yet it reasons only when asked. This is now noted, like Ornith's mismatch.
  - `finetune/README.md`'s "well inside the spread" was not literally true.
  - The ternary model's share in higher precision is now given "of its language-model weights".
  - Two restart times in its README were 17:36 and 17:37; both now read 17:36.
  - The `models.yaml` comment on its server flags was wrong.
  - The conclusion grouped the ternary laptop result under "larger hardware".
  - §9's sample counts now include the box fine-tunes.
  - "Chat models" replaces "language models" where the store's set is counted, since the store also holds embedding, reranking and OCR models.
  - "Four training stages."
- **Code:**
  - `sample_stats.py` now drops flagged records within each folder before merging, exactly as `analyze.py` does.
  - `analyze.py` now also skips records whose attempts are not objects, where it used to crash.
  - The redaction's home-directory pattern gained a left boundary, so `/data/home/...` is left alone.
  - The bench README described the superseded-files folder before the harness wrote it. The harness change has since landed, and the Bonsai rerun's predecessor sits where the harness would have put it.
