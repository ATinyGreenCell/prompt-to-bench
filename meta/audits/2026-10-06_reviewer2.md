# Adversarial review ("Reviewer 2"): code, numbers, designs and prose

Snapshot: HEAD `0e77486` plus working tree, 6 Oct 2026 ~18:00, while the Qwen3.5 4B local run was still writing `bench/results/main/`. Three reviewers (harness code, every number against the data, designs) ran in parallel with one prose pass; all were report-only, and fixes were applied afterwards. Like the earlier audits, this was done by Claude, which also wrote the work, so it is not independent review.

## Fixed

**Checker (could let wrong parts pass)**
- Two `line` checks on the gel comb had the same name (`line z=0.75`), and results are keyed by name, so the spine check overwrote the 10-teeth check. A 9-tooth comb and a comb with 0.5 mm gaps both passed. Repeated names are now numbered (`checks.py`), and comb probes pin the tooth pitch.
- A one-groove micropestle and a knob with a 7 mm bore (instead of 12) passed. Added slices at z = 15, 20, 25 (pestle) and z = 11.5 (knob).
- An arc with no material counted as one gap. It now fails.
- These four wrong parts are now in `bench/mutants/`. `build_refs.py` requires them to fail.
- `build_refs.py` no longer overwrites the frozen `reference_stats.json`. It compares against it unless `--write` is passed.
- Re-checking all hosted-model and Swahili attempts with the new checks changed no verdict, only partial scores.

**Data and analysis**
- The Swahili code files of `lang-claude` had no language suffix, so `rescore.py` and `analyze.py` never found them. They have been renamed `*_sw_a*` and re-checked.
- After the funnel rescore, Sonnet's first attempt passed, but the repair attempt that followed was still counted ("0/1 same code", "0/17 attempts"). `analyze.py` now drops attempts after the first pass.
- "Geometry as a value" was counted on LFM2.5's unfenced reasoning prose. It now counts only extracted code blocks.
- `analyze.py` now computes the language McNemar tests. It also takes `--runs`, so a contributor's own run can be analysed, and dead figure code was removed.
- `run_bench.py` records the decisive OpenSCAD message when there are more than 10, and keeps "mesh analysis failed" in the record. Its dirty-tree flag no longer fires on results and logs.
- `rescore.py` reports failed re-renders and pass-to-fail flips instead of silently keeping old verdicts.
- `slice_library.py` dropped the seconds from print times, so the total was 32.8 h instead of 33.0 h. After the design fixes below it is 33.7 h, 508 g.
- `pull_models.sh` was missing `qwen2.5:1.5b`, and the README reproduce steps had no pull step. `make lang` ran a local language run that the paper says was not done.

**Designs**
- The seed template's lift tab made it 86.7 mm long, so it no longer fit inside a 90 mm dish. The tab is now a tweezer slot inside the disc.
- In the slide rack, slides could lean about 11° in their slots and touch their neighbours. The slots are now 6 mm deep at an 8 mm pitch, the block grows with the slot count, and drain channels run under the block.
- The clearance coupon covered only 0-0.25 mm per side, which cannot find the 0.3-0.5 mm "loose" fit the paper recommends. It now goes to +1.0 mm on the diameter, the plate follows `pitch`, and the peg is chamfered against elephant's foot. The print time is about 35 min, not 15.
- The funnel's true-wall fix had left a 0.5 mm lip and a 5.8 mm throat at the spout. The bore now continues into the cone.
- Hose barb: the header said 3 mm bore against the actual 2.5 mm. There was a flat 1.25 mm overhang under the collar, now a 45° cone. The advice no longer suggests it for biological aspiration.
- Rod clip: the default gave no grip on a 1/2" rod. The snap openings and ring spacing now follow the measured diameters.
- The tube and 50 mL racks had fixed block sizes. Following the tutorial's "change `cols`" instruction would have cut holes through the side. The blocks are now computed from the grid.
- Gel tank: added "+"/"−" polarity marks, and dropped the claim that the comb fits the tank.
- The adapter, knob, tube-rack and seed headers were corrected.
- Every design described its parameters in trailing comments, which the Customizer ignores, and decimal values stepped by 1 mm. Each description is now on the line above its parameter, and decimal values have a step.

**Paper and docs**
- No user study backs "reliable for people without CAD training" or "a practical way for a biologist without CAD training". These claims are reworded, and the gap is added to §9.
- §3 said "two features of the loop matter more than the choice of model". The results show that the model choice decides everything here.
- Corrected: the McNemar p-values (0.375, 0.125), Sonnet's 3.5-11.5 s, the truncation counts (complete runs only), the bridge and support claims, and the slip-fit title.
- "Failures differed between languages, as sampling noise would produce" was wrong. The NEMA 17 bracket failed in all three translations with the same check.
- The audits are no longer called "independent".
- The tutorial overstated feedback ("helped the hosted models fix most…") and "tips that make small models work better" (untested).
- Removed filler: slogans, "literally", "the single best investment", "That is all OpenSCAD is", "We hope others will", and the opener of §8.

## Follow-up, 7 Oct 2026: edge cases and hardening (v0.2.0)

**Harness.** About 75 new tests in `bench/test_harness.py` cover:
- extraction: fence variants, CRLF, `<think>` blocks, empty, `None`, unicode and 2 MB replies;
- rendering: missing imports, timeouts, non-manifold or disjoint parts, parts below z = 0, paths with spaces, non-UTF-8 OpenSCAD output;
- the checker: degenerate, empty or NaN meshes against all 16 tasks;
- a fake Ollama server: not running, model missing, a non-Ollama answer, an error mid-stream;
- argument errors, damaged or foreign result lines, and missing tools.

Fixes:
- Crashes on non-UTF-8 OpenSCAD output and on surrogate or `None` replies.
- A missing Claude CLI used to retry for about 10 min per task; it is now refused before the run starts.
- A non-Ollama answer on the port used to wait 300 s; it now fails at once.
- Unknown `--tasks` and impossible arguments ran nothing or crashed. They are now refused before the run starts.
- A quadratic-time fence regex.
- A stale STL could be reused after a failed render.
- Clean errors when OpenSCAD or PrusaSlicer is missing.

Non-regression:
- 0 verdict or score changes when all 290 saved conversations are rescored;
- identical extraction on all 705 saved replies;
- identical scadreport output on 125 parts;
- `reference_stats.json` and the `analyze.py` output unchanged.

**Designs.**
- Every design now stops with an `assert()` message when its parameters would make a broken or unsafe part, such as overlapping holes, a floor or wall under 0.8 mm, a gel-tank groove that could leak, or a bore that breaks through.
- `tools/check_designs.py` (`make designs`) renders each design with its defaults and with 39 edge-case parameter sets.
- This found a real defect: the D-shaft knob rendered as 41 bodies and was not watertight, because the round mouth bore and the D bore had coincident faces. Fixed by rotating the round section half a facet.

**Build log.** An earlier session's grep command had put a bare e-mail local part and a fragment of a private string into `meta/BUILD_LOG.md`. `build_log.py` now redacts bare `user@` strings, and the log was re-scanned before release.

**Found, not fixed** (a fix would change how the remaining Qwen3.5 9B run is scored):
- An Ollama stream that ends without `done` is scored as the model's reply instead of being retried. One record is affected: granite4.2:3b, stirrer housing, attempt 3, which was a fail either way.
- `~~~` fences and a code block nested inside another block are not extracted. No saved reply has either.
- A missing local model is only detected when the run reaches it.
